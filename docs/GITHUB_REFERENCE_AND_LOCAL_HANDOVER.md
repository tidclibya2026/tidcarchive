# GitHub كنسخة مرجعية لنظام TIDC

يبقى مستودع GitHub الخاص بـ TIDC هو **النسخة المرجعية للكود والوثائق وحزمة التنصيب** خلال مرحلة التطوير والتدريب. يشمل ذلك الواجهة العربية، الخادم وواجهات tRPC، مخطط قاعدة البيانات وترحيلاتها، خدمة OCR، ملفات النسخ الاحتياطي، ملفات الحاويات، ودليل تشغيل الخادم المحلي.

## ما يُحفظ في GitHub

| المحتوى | الغرض |
|---|---|
| `client/` و`server/` و`shared/` | واجهة النظام ومنطق الأعمال والمصادقة والصلاحيات. |
| `drizzle/` | مخطط قاعدة البيانات والترحيلات. |
| `ops/local-windows/` | حزمة تشغيل الخادم المحلي وفحصه وتقارير الاستلام. |
| `ops/ocr/` و`ops/backup/` | خدمة OCR وإجراءات النسخ الاحتياطي والاستعادة. |
| `docs/` | أدلة التشغيل والأمن والشبكة وخطة الاستلام. |
| `todo.md` | سجل قابل للمراجعة للمنجز والبنود التشغيلية المعلقة. |

لا يحفظ المستودع كلمات المرور أو ملف `.env` أو مفاتيح التشفير أو ملفات النسخ الحية أو مرفقات المعاملات الحقيقية. تبقى هذه العناصر على الخادم المحلي أو في نظام إدارة أسرار معتمد فقط.

## ما لا يقدمه GitHub Pages

GitHub Pages خدمة صفحات ثابتة. لا تشغل خادم Express أو قاعدة MySQL أو MinIO أو OCR أو حسابات الدخول المحلية. لذلك لا يستخدم رابط Pages لتشغيل نظام TIDC الكامل أو تدريب الموظفين على بيانات حقيقية؛ يستخدم فقط، عند الحاجة، لصفحة تعريفية أو وثائق ثابتة.

> تشغيل التدريب العملي والنظام النهائي يحتاج بيئة تطبيق كاملة تشمل الخادم وقاعدة البيانات والتخزين، ثم تنقل هذه البيئة إلى خادم المركز المحلي بعد الاستلام التقني.

## مسار النقل إلى الخادم المحلي

1. يحفظ كل تغيير معتمد في GitHub عبر نسخة مراجعة.
2. يستنسخ مسؤول التقنية النسخة المعتمدة من المستودع إلى `C:\Archiving` أو إلى بيئة Linux المدعومة بحسب نظام الخادم.
3. ينشئ المسؤول ملف الأسرار المحلي الجديد، ولا ينسخ `.env` من بيئة التطوير.
4. يضبط DNS الداخلي `tidc.ly` وجدار الحماية والشهادة حسب دليل الاستلام الفني.
5. يشغل فحص ما قبل التنصيب، ثم الحزمة، ثم تقرير الاستلام الآمن.
6. تنقل البيانات المعتمدة فقط بعد اختبار النسخ والاستعادة في بيئة معزولة.

## التحقق المرجعي

قبل النقل، يتحقق مسؤول التقنية من وجود الملفات الأساسية في الفرع `main`: `client/src/App.tsx`، `server/routers.ts`، `drizzle/schema.ts`، `ops/local-windows/docker-compose.yml`، `ops/local-windows/Install-TIDC.ps1`، ودليل التشغيل الفني. ثم يشغل اختبارات المشروع والبناء من النسخة المعتمدة قبل التنفيذ على الخادم.
