# تشغيل ونقل نظام الأرشفة الإلكترونية — TIDC

## هدف النسخة الحالية

هذه النسخة هي تطبيق ويب عربي متجاوب مبني على React وExpress وtRPC وDrizzle مع قاعدة بيانات MySQL/TiDB وتخزين كائني للمرفقات. صُمّمت لتجارب التطوير والتحقق أولًا، ثم للنقل إلى خادم محلي بعد اعتماد البنية الأمنية، النطاقات الداخلية، وخدمات التخزين الاحتياطية.

## متطلبات الخادم المحلي

| المكوّن | المتطلب التشغيلي |
|---|---|
| نظام التشغيل | Linux مدعوم ومحدّث، مع حساب خدمة مخصص للتطبيق. |
| وقت التشغيل | Node.js 22 وpnpm، مع متغير `NODE_ENV=production`. |
| قاعدة البيانات | MySQL 8 أو TiDB متوافق، مستخدم تطبيق بأقل صلاحيات لازمة وقاعدة مخصصة للنظام. |
| الملفات | تخزين كائني متوافق مع S3 داخل الشبكة، مثل MinIO، مع نسخة احتياطية مستقلة. لا تُحفظ الملفات داخل قاعدة البيانات. |
| الولوج | نطاق داخلي محمي عبر HTTPS وشهادة موثوقة؛ HTTPS أساسي لعمل التقاط الصور من كاميرا الهاتف. |

## خطوات النقل المقترحة

ابدأ بنسخة نظيفة من المستودع المعتمد، وثبّت الحزم باستخدام `pnpm install --frozen-lockfile`. تُدار قيم الاتصال وقيم المصادقة والتخزين في مدير أسرار الخادم أو متغيرات بيئة محمية، ولا تُضاف إلى المستودع أو الوثائق. بعد التحقق من الاتصال بقاعدة البيانات، طبّق ملفات الترحيل المراجعة في مجلد `drizzle/migrations` باستخدام إجراءات النشر المعتمدة في بيئة المؤسسة.

يجب تهيئة مخزن S3 المحلي، ثم مواءمة محول التخزين في `server/storage.ts` مع نقطة نهاية التخزين الداخلية وبيانات اعتماد حساب خدمة مقيّدة بمسار النظام. يحتفظ النظام في قاعدة البيانات بمفتاح الملف ومساره وبياناته الوصفية فقط؛ أمّا البايتات فتُرفع إلى المخزن الكائني. لا تُنقل أو تُضمّن أي كلمات مرور واردة في ملفات البنية التحتية المرجعية ضمن إعدادات التطبيق.

بعد البناء عبر `pnpm build`، شغّل `pnpm start` خلف وكيل عكسي داخلي. ينبغي حصر نقطة الدخول في HTTPS، وتمرير رؤوس البروكسي الموثوقة فقط، وتعطيل الوصول العام إلى قاعدة البيانات ومخزن الملفات. اختبر تسجيل الدخول، إنشاء معاملة، رفع PDF، التصوير من الهاتف، الإحالة، البحث، وسجل الإجراءات قبل فتح النظام للمستخدمين.

## إدارة الأدوار والاستمرارية

تبدأ الحسابات بدور **موظف**؛ ثم يعيّن مسؤول تقنية المعلومات الأدوار المؤسسية بعد التحقق من هوية المستخدم وإدارته. الأدوار المتاحة هي: مدير عام، مكتب متابعة، رئيس إدارة، موظف، وإدارة تقنية المعلومات. يجب مراجعة التعيينات دوريًا مع الهيكل التنظيمي.

نفّذ نسخة احتياطية مجدولة ومشفرة لقاعدة البيانات ولمخزن الكائنات، مع اختبار استعادة دوري في بيئة معزولة. يُنصح كذلك بحفظ سجل التدقيق وفق سياسة الاحتفاظ المعتمدة لدى المركز. ميزة OCR الحقيقية للمحتوى داخل PDF والصور ليست جزءًا من هذه النسخة؛ يدعم البحث الحالي النصوص والملخصات المفهرسة وأسماء المرفقات، ويمكن إضافة خدمة OCR داخلية معتمدة في مرحلة لاحقة.
