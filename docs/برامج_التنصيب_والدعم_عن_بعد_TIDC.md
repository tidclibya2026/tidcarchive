# البرامج المطلوبة والدعم عن بُعد لنظام TIDC

يوضح هذا الدليل ما ينزله كل طرف لتشغيل النظام في ليبيا مع دعم من مصر. لا يتطلب النظام تنزيل MySQL أو MinIO أو Node.js أو Python أو Tesseract على خادم المركز؛ فهي تأتي داخل الحاويات التي تشغلها الحزمة.

## القرار الأول: نظام تشغيل الخادم

| نظام الخادم | المسار المعتمد للحزمة الحالية |
|---|---|
| **Windows 10/11 Pro أو Enterprise، 64-bit** | استخدم Docker Desktop مع WSL 2؛ هذا هو المسار المدعوم لحزمة `C:\Archiving`. |
| **Windows Server** | لا تشغّل Docker Desktop؛ توثيق Docker يذكر أنه غير مدعوم على إصدارات Windows Server. جهز خادماً افتراضياً أو جهازاً مخصصاً بنظام Linux مدعوم، ثم يطلب مسؤول التقنية حزمة Linux المناسبة قبل التنفيذ. |

> المركز جهة حكومية؛ يلزم أن يراجع مسؤول المشتريات أو تقنية المعلومات شروط ترخيص Docker Desktop قبل استخدامه مؤسسياً، لأن شروط Docker تختلف حسب نوع وحجم الجهة.[1]

## ما الذي ينزله مسؤول التقنية في ليبيا؟

| البرنامج | متى يستخدم | مصدر رسمي أو ملاحظة |
|---|---|---|
| Docker Desktop for Windows (AMD64) | فقط إذا كان الخادم Windows 10/11 مدعوماً. | [صفحة Docker الرسمية][1] |
| WSL 2 | عند اختيار Docker Desktop/WSL 2؛ يفعله مسؤول النظام كشرط لمرة واحدة. | `wsl --install` ثم إعادة التشغيل عند الطلب.[1] |
| حزمة TIDC المضغوطة | تفك داخل `C:\Archiving` وتشغل `Install-TIDC.cmd`. | المرفقة من فريق النظام. |
| Quick Assist | اختياري لجلسة دعم مرئية وموافَق عليها فقط. | Microsoft Store أو البحث في Windows.[2] |
| Microsoft Edge أو Google Chrome | فتح `https://tidc.ly:8443` بعد تثبيت شهادة الجذر الداخلية. | غالباً مثبت مسبقاً. |

يجب أن يعمل Docker Desktop قبل تشغيل ملف التثبيت. تحتاج الحزمة إلى 12 GB ذاكرة كحد موصى به و60 GB مساحة حرة. يتطلب Docker Desktop مع WSL 2 معالجاً 64-bit ودعم الافتراضية في BIOS/UEFI وWSL حديثاً؛ يتحقق ملف الفحص المسبق في الحزمة من Docker والموارد والمنافذ وDNS، لكنه لا يثبت Docker نيابة عن مسؤول النظام.[1]

## ما الذي تحتاجه أنت في مصر؟

تحتاج فقط إلى متصفح حديث للوصول إلى معاينة النظام وإلى وسيلة اتصال موثوقة مع مسؤول التقنية. لا تحتفظ بملف `.env` ولا كلمات مرور مدير النظام ولا مفاتيح التشفير على جهازك. إذا تقرر استخدام Quick Assist، ثبت التطبيق من متجر Microsoft الرسمي فقط، ولا تبدأ جلسة إلا عندما يكون مسؤول التقنية المحلي بجانب الخادم ويعلم بوقت الجلسة.[2]

## بروتوكول الدعم عن بُعد الآمن

1. يحدد الطرفان موعداً ويشغل مسؤول التقنية المحلي Docker Desktop ويجلس أمام الخادم.
2. يبدأ المسؤول المحلي Quick Assist من Windows عبر `Ctrl + Windows + Q`، ويختار **Get help** عند الحاجة.
3. يفتح المساعد في مصر Quick Assist بحساب Microsoft شخصي أو مؤسسي موثوق، ويختار **Help someone**؛ يولد التطبيق رمزاً مؤقتاً من ستة أرقام.
4. يرسل الرمز في قناة اتصال متفق عليها، ويدخله المسؤول المحلي ويوافق صراحة على مشاركة الشاشة. يبدأ الوضع بعرض الشاشة فقط.
5. لا يطلب التحكم الكامل إلا عند تنفيذ خطوة محددة، ويوافق المسؤول المحلي أو يرفض. يبقى المسؤول المحلي هو من يكتب كلمات مرور Docker وملف `.env` وكلمة مرور مدير TIDC.
6. بعد تنفيذ `Install-TIDC.cmd` و`Test-TIDC-Installation.ps1 -WriteReport`، ينهي الطرفان الجلسة ويشارك المسؤول المحلي التقرير الآمن فقط.

تستخدم Quick Assist اتصال HTTPS خارجياً على المنفذ 443 وتحتاج الإنترنت من الطرفين، ولا تتطلب فتح منفذ RDP وارد أو تعريض خادم TIDC للإنترنت. يجب السماح بالاتصال فقط مع شخص موثوق بدأت المؤسسة التواصل معه؛ لا تشارك كلمات المرور أو مفاتيح التشفير أو ملفات `.env` في جلسة الدعم أو الدردشة.[2] [3]

## توزيع المسؤوليات

| المهمة | مسؤول التقنية في ليبيا | المستخدم/المتابع في مصر |
|---|---|---|
| نظام الخادم وDocker | يثبت ويتحقق من توافق النظام والترخيص. | يراجع دليل الحزمة ولا يثبت برامج على خادم المركز دون تنسيق. |
| الشبكة | يثبت DNS الداخلي لـ `tidc.ly` وقاعدة جدار 8443. | يراجع تقرير الاختبار فقط. |
| الأسرار | ينشئ كلمة مرور المدير ويحفظ `.env` في الخادم فقط. | لا يستلم الأسرار. |
| التثبيت | يشغل `Install-TIDC.cmd` محلياً. | يقدم إرشاداً عبر مشاهدة الشاشة عند الحاجة. |
| التحقق | يشغل تقرير الحالة ويحتفظ به. | يراجع التقرير ويحدد أي خطوة تالية. |
| التشغيل اليومي | يدير Docker والنسخ والتحديثات محلياً. | يستخدم النظام ويدير المتطلبات الإدارية. |

## قبل البدء

يؤكد مسؤول التقنية أولاً اسم إصدار Windows عبر `winver`. إذا كان النظام Windows Server، يتوقف عن تنزيل Docker Desktop ويرسل نوع الإصدار وموارد الخادم حتى يتم إعداد مسار Linux منفصل. إذا كان Windows 10/11 مدعوماً، ينزل Docker Desktop من الموقع الرسمي ويشغله، ثم ينفذ:

```powershell
C:\Archiving\ops\local-windows\Test-TIDC-Preflight.ps1 -TlsMode internal -Hostname tidc.ly
```

لا يبدأ التثبيت إذا فشل الفحص في Docker أو المساحة أو DNS أو المنفذ. بعد معالجة الخطأ، يعيد المسؤول الفحص ثم يتابع التنصيب.
