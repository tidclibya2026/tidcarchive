# ضوابط الأمن والتشغيل — نظام TIDC

يوضح هذا الدليل الضوابط التي تطبقها النسخة الحالية، وما يبقى إجراءً تشغيلياً على خادم الشؤون الإدارية. لا يمثل أي ضابط برمجي بديلاً عن إدارة كلمات المرور، وصلاحيات Windows، ونسخ المفاتيح، والمراجعة الدورية لسجلات الحوادث.

## مصفوفة الضوابط

| المجال | الضابط المنفذ في النظام | الإجراء التشغيلي المطلوب |
|---|---|---|
| النقل | بوابة HTTPS محلية عبر Caddy، وHSTS عند الاتصال الآمن، وجلسات محلية بملفات تعريف ارتباط `HttpOnly` و`Secure` و`SameSite=Strict` عبر HTTPS. | تثبيت شهادة الجذر الداخلية الصادرة عن Caddy أو شهادة مؤسسية على أجهزة المركز، وحظر الوصول الشبكي عبر HTTP. |
| التخزين | تشفير المرفقات محلياً قبل وضعها في MinIO باستخدام **AES-256-GCM** ومفتاح 256 بت منفصل لكل عملية تنصيب؛ ويبقى MinIO خارج الشبكة العميلة. | نسخ مفتاح `DOCUMENT_ENCRYPTION_KEY` مشفراً ضمن خزينة أسرار مستقلة؛ فقدانه يمنع استعادة المرفقات. |
| الملفات | قائمة أنواع مسموحة فقط: PDF وJPEG وPNG وWebP، وفحص للترميز والحجم والتوقيع الثنائي والاسم، وإعادة تسمية آمنة، وتحكم في الصلاحية قبل التخزين. | تشغيل ClamAV والمحافظة على تحديث تواقيعه؛ لا تقبل استثناءات للفحص عند تعذر الخدمة. |
| الجلسات والهوية | رمز جلسة محلي موقع وينتهي بعد ثماني ساعات، ولا يظهر في JavaScript؛ ويدقق الخادم في الحساب والصلاحيات مع كل إجراء. | استخدم HTTPS دائماً، وغيّر كلمة مرور المدير الأولية فور تنصيب بيئة إنتاجية. |
| الواجهة | CSP مقيد، ومنع التضمين عبر `frame-ancestors` و`X-Frame-Options`، ومنع MIME sniffing، وسياسة مراجع مقيدة. لا تستخدم الواجهة حقن HTML للمحتوى الذي يدخل من المستخدم. | أضف أي مصدر خارجي جديد إلى CSP فقط بعد مراجعته واعتماده. |
| مقاومة الإساءة | حدّ طلبات لمحاولات تسجيل الدخول والرفع، وردود `429` عند تجاوز الحدود، مع التحقق المؤسسي من كل مسار API محمي. | راقب سجلات Caddy والتطبيق، وانقل حد المعدل إلى مخزن مشترك إذا توسع النظام لأكثر من عقدة تطبيق واحدة. |
| النسخ والتعافي | سكربتات نسخ MySQL وMinIO مشفرة، واحتفاظ خارجي، واستعادة معزولة أسبوعية في حزمة التشغيل المؤسسية. | شغّل النسخة الأولى واختبار الاستعادة على خادم المركز، ووثق الزمن وعدد كائنات MinIO والنتيجة. |

## إجراءات التنصيب الآمن على Windows

شغّل `Install-TIDC.cmd` ثم شغّل `Test-TIDC-Installation.ps1` من PowerShell. يجب أن يعرض الاختبار حالة الخدمات ورؤوس `Strict-Transport-Security` و`Content-Security-Policy` و`X-Frame-Options` و`X-Content-Type-Options`. استخدم اسم DNS ثابتاً بدلاً من عنوان IP في حقل `TIDC_HOSTNAME`، ثم صدّر شهادة Caddy الجذرية من الحاوية وثبّتها في مخزن **Trusted Root Certification Authorities** على أجهزة المركز المصرح لها فقط.

> لا تفتح منافذ MySQL أو MinIO أو OCR أو ClamAV في جدار حماية Windows. منفذ HTTPS وحده هو الذي يواجه شبكة المركز، بينما تبقى بقية الخدمات على شبكة حاويات داخلية معزولة.

يحفظ ملف `ops\local-windows\.env` أسرار التشغيل، ومنها مفتاح تشفير المرفقات. يمنح السكربت صلاحية الملف للمستخدم الذي أجرى التنصيب فقط. يجب أن تراجع إدارة التقنية هذه الصلاحية عند تغير مالك الخادم أو حساب الخدمة، ولا يجوز وضع الملف في Git أو إرساله عبر البريد.

## النسخ الاحتياطي والتعافي من الكوارث

يجب أن تنتج عملية النسخ اليومية نسخة MySQL ونسخة MinIO، ثم تشفرهما قبل النقل إلى وجهة منفصلة عن شبكة الإنتاج. يجب أن تضم النسخة المشفرة أيضاً نسخة محمية من `DOCUMENT_ENCRYPTION_KEY`؛ استعادة أقراص MinIO وحدها لا تكفي لفك محتوى المرفقات. لا تستخدم بيئة الاستعادة نفس قاعدة البيانات أو bucket الإنتاج.

يجرى اختبار استعادة أسبوعي معزول، وتجرى تجربة تعافٍ كاملة ربع سنوية. يوثق لكل تجربة وقت البدء والانتهاء، وقاعدة البيانات المستعادة، وعدد الكائنات، وعينة من المستندات المفكوكة، وأي فروق، والقرار التصحيحي. يعتمد نجاح التعافي على تحقيق أهداف الزمن ونقطة الاستعادة التي تعتمدها إدارة المركز، وليس على اكتمال النسخ فقط.

## إدارة التحديثات والثغرات

تخصص نافذة صيانة شهرية على الأقل لمراجعة تحديثات Windows وDocker Desktop وصور MySQL وMinIO وCaddy وClamAV وتبعيات Node وPython. يختبر التحديث أولاً في نسخة معزولة؛ ثم تؤخذ نسخة احتياطية مشفرة، ويُحدّث النظام، ويُنفذ `Test-TIDC-Installation.ps1`، ويُراجع سجل OCR ورفع ملف اختبار آمن. تطبق معالجة عاجلة للثغرات الحرجة وفق تقييم إدارة التقنية، مع الاحتفاظ بإصدار معروف صالح وخطة رجوع.

## الحدود المهمة

يعد فحص ClamAV طبقة دفاع إضافية ولا يلغي تحقق التوقيع أو الصلاحيات أو الحجم؛ فهي ضوابط متكاملة كما توصي إرشادات OWASP.[1] لا يكفي تشفير جانب العميل أو وضع مفتاح ثابت داخل الكود. يستخدم MinIO نموذج مفاتيح منفصلاً عند تفعيل تشفيره الخادمي SSE-S3، وهو يتطلب خدمة إدارة مفاتيح صالحة؛ لذلك لا تفعل SSE-S3 بمفتاح مضمّن أو غير مدعوم.[2]
