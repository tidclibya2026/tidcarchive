# تجهيز التخزين المحلي وHTTPS — نظام TIDC

## الهدف التشغيلي

يُستخدم MinIO كمخزن كائني داخلي لمرفقات المراسلات وملفات PDF وصور الهاتف، بينما تحفظ قاعدة البيانات المفاتيح والبيانات الوصفية فقط. يعمل تطبيق TIDC خلف وكيل عكسي HTTPS حتى تدعم كاميرا الهاتف وإدارة الجلسات اتصالًا آمنًا داخل شبكة المركز.

| طبقة التشغيل | الدور | ضابط أساسي |
|---|---|---|
| التطبيق | واجهة React وخادم Node/tRPC | يعمل بحساب خدمة مستقل، ولا تُحفظ الأسرار في المستودع. |
| MySQL/TiDB | بيانات المعاملات والمستخدمين وسجل التدقيق | حساب قاعدة بيانات بأقل الصلاحيات ونسخة احتياطية يومية. |
| MinIO | ملفات PDF والصور والمرفقات | Bucket خاص، وسياسة وصول من الخادم فقط. |
| Nginx | HTTPS، تمرير الطلبات، وحدود الرفع | يسمح بمرور HTTPS فقط ويضيف رؤوس البروكسي الموثوقة. |

## MinIO داخل الشبكة

أنشئ مثيل MinIO على خادم محلي أو خادم تخزين معتمد، ثم أنشئ bucket خاصًا مثل `tidc-archive`. أنشئ حساب خدمة للتطبيق بسياسة تقتصر على `GetObject` و`PutObject` و`DeleteObject` لمسار bucket الخاص بالنظام. لا تستخدم حساب MinIO الجذري داخل التطبيق، ولا تضع مفاتيح MinIO في ملفات Git أو ملفات الواجهة الأمامية.

تُحفظ القيم التالية في مدير أسرار الخادم أو ملف بيئة محمي خارج المستودع:

```bash
S3_ENDPOINT=https://minio.tidc.local
S3_REGION=local
S3_BUCKET=tidc-archive
S3_ACCESS_KEY=<service-account-access-key>
S3_SECRET_KEY=<service-account-secret-key>
```

يجب أن تتوافق نقطة النهاية مع واجهة S3، وأن يبقى bucket خاصًا. عند النقل النهائي، تُراجع دالة التخزين في `server/storage.ts` لتستخدم القيم المحلية دون تغيير مخطط المرفقات أو منطق أرشفة PDF.

## HTTPS والوكيل العكسي

اربط اسمًا داخليًا ثابتًا مثل `archive.tidc.local` بعنوان الخادم في DNS الداخلي. ضع Nginx أمام التطبيق، وأنهِ TLS في Nginx باستخدام شهادة صادرة من سلطة شهادات المؤسسة أو من سلطة موثوقة. يمرر Nginx الطلبات إلى منفذ التطبيق المحلي ويضبط `X-Forwarded-Proto: https`. لا تُفتح منافذ قاعدة البيانات أو MinIO أو Node مباشرة أمام المستخدمين.

مثال هيكلي مختصر للوكيل العكسي، مع استبدال المسارات والشهادات في بيئة المركز:

```nginx
server {
  listen 443 ssl http2;
  server_name archive.tidc.local;

  ssl_certificate     /etc/ssl/tidc/archive.crt;
  ssl_certificate_key /etc/ssl/tidc/archive.key;
  client_max_body_size 12m;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
  }
}
```

> يجب حظر HTTP أو تحويله إلى HTTPS. سياق HTTPS ضروري للوصول الموثوق إلى كاميرا الهاتف ولإرسال ملفات تعريف ارتباط الجلسات بأمان.

## النسخ الاحتياطي والاستعادة

نفّذ نسخة احتياطية مشفرة يوميًا لقاعدة البيانات، ونسخة متزامنة من bucket إلى وسيط تخزين منفصل داخل المؤسسة. احتفظ بنسخ دورية وفق سياسة المركز، واختبر الاستعادة في بيئة معزولة كل ثلاثة أشهر على الأقل. لا يعتبر نجاح النسخ الاحتياطي نجاحًا تشغيليًا إلا بعد اختبار استعادة قاعدة البيانات وملف PDF واحد على الأقل والتحقق من توافق سجل المرفق.

## قائمة اعتماد قبل التشغيل

تحقق من أن شهادة HTTPS صالحة في هاتف وشبكة المركز، وأن حساب خدمة MinIO لا يملك صلاحيات إدارية، وأن رفع PDF والتصوير من الهاتف ينجحان، وأن الحساب الإداري المحلي يسجل الدخول عبر HTTPS، وأن النسخة الاحتياطية الأخيرة قابلة للاستعادة. بعد هذه الاختبارات، يمكن تحويل النظام من وضع التجربة على GitHub إلى بيئة التشغيل المحلية وفق إجراءات تقنية المعلومات المعتمدة.
