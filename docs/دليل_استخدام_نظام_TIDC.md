# دليل استخدام نظام الأرشفة الإلكترونية والمتابعة — TIDC

هذا الدليل موجه للمديرين والموظفين ومسؤول النظام في مركز المعلومات والتوثيق السياحي. يوضح رحلة العمل من تسجيل الدخول إلى إدخال المعاملات ورفع المستندات والإحالات والأرشيف والتقارير. استخدم فقط بيانات تدريب غير حقيقية عند التدريب، ولا ترفع وثائق حكومية فعلية قبل تشغيل الخادم المحلي واعتماد سياسة المركز.

## 1. الدخول وكلمة المرور

عند فتح رابط النظام تظهر **شاشة تسجيل الدخول** أولاً. يدخل المستخدم بريده المؤسسي وكلمة المرور التي أنشأها أو استلمها من مسؤول النظام. لا تُكتب كلمة مرور المدير الأولية أو أي كلمة مرور في GitHub أو في ملفات التدريب أو رسائل البريد العامة.

بعد الدخول، تظهر لوحة القيادة وفق صلاحية الحساب. يسجل المستخدم خروجه من القائمة الموجودة أسفل القائمة الجانبية عند انتهاء العمل، خصوصاً عند استخدام جهاز مشترك. في بيئة الخادم المحلي يجب تغيير كلمة المرور الأولية فور التسليم وحفظها في إجراء مؤسسي معتمد.

| الدور                                                    | نطاق العمل الأساسي                                                                    |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| المدير العام ومدير مكتب المدير العام ومدير مكتب المتابعة | متابعة شاملة، تقارير، أرشيف، وإجراءات إدارية وفق الصلاحيات التنفيذية المعتمدة.        |
| رئيس الإدارة أو المكتب                                   | عرض ومعالجة المعاملات التابعة للوحدة، الإحالات، والمتابعة.                            |
| الموظف                                                   | إدخال ومعالجة المعاملات ضمن نطاق إدارته وصلاحياته.                                    |
| مدير النظام                                              | إدارة المستخدمين والتفعيل والتعطيل وسجل تدقيق الحسابات، إضافة إلى الصلاحيات المعتمدة. |

## 2. لوحة القيادة والتنقل

بعد الدخول تعرض لوحة القيادة ملخص المعاملات النشطة والمتأخرة وقيد المعالجة والمنجزة والمؤرشفة. من القائمة اليمنى يستطيع المستخدم فتح الوارد والصادر والقرارات والمناشير ومكتب المتابعة والأرشيف والتقارير. تظهر إدارة المستخدمين وسجل التدقيق فقط للحساب المصرح له إدارياً.

> لا تمنح الواجهة وحدها صلاحية إضافية؛ يفحص الخادم الدور والوحدة التنظيمية في كل إجراء مهم.

## 3. تسجيل مراسلة واردة أو صادرة

يفتح المستخدم **المراسلات الواردة** أو **المراسلات الصادرة** ثم يضغط **تسجيل وارد جديد** أو **تسجيل صادر جديد**. يولد النظام الرقم الرسمي تلقائياً بعد الحفظ؛ لا يكتب المستخدم الرقم يدوياً.

| الحقل                 | ما الذي يكتب فيه؟                                               |
| --------------------- | --------------------------------------------------------------- |
| الموضوع               | عنوان واضح للمراسلة لا يقل عن كلمات مفهومة.                     |
| الجهة                 | الجهة المرسلة في الوارد أو الجهة المستقبلة في الصادر.           |
| تاريخ الوثيقة         | تاريخ الخطاب أو الكتاب الرسمي.                                  |
| درجة الأهمية          | عادي أو عاجل أو سري بحسب التصنيف الإداري.                       |
| الإدارة المحال إليها  | الإدارة أو المكتب المعني، أو يترك دون إحالة أولية عند الحاجة.   |
| تاريخ الاستحقاق       | آخر تاريخ مطلوب للرد أو الإنجاز؛ لا يجوز أن يسبق تاريخ الوثيقة. |
| ملخص أو نص قابل للبحث | وصف موجز يسهل العثور على المعاملة لاحقاً بالبحث العربي.         |

في المراسلة الصادرة يمكن اختيار مراسلة واردة مرجعية عند وجودها. بعد المراجعة يضغط المستخدم **حفظ وتسجيل**؛ تظهر رسالة نجاح تحتوي الرقم الرسمي الذي تم إنشاؤه.

## 4. رفع المستندات والتصوير من الهاتف

داخل نموذج المراسلة توجد منطقة **المرفقات الرقمية**. يختار المستخدم **رفع ملف** لإرفاق PDF أو صورة موجودة، أو **تصوير** من الهاتف لفتح الكاميرا الخلفية وتصوير المستند.

يسمح النظام بملفات PDF وJPEG وPNG وWebP فقط، وبحد أقصى 10 MB للملف في الواجهة. يعيد الخادم التحقق من نوع الملف وتوقيعه وحجمه واسم الملف، ثم يفحصه قبل التخزين. لا يرفع المستخدم ملفات تنفيذية أو أرشيفات مضغوطة أو مستندات غير مصرح بها.

بعد الالتقاط تظهر معاينة للصور وحالة كل ملف؛ يستطيع المستخدم حذف مرفق قبل الحفظ. عند حفظ المعاملة يرفع النظام المرفقات ويعرض حالة الرفع. تستخدم خدمة OCR النص الموجود في PDF والصور لإتاحته في البحث، ويظهر وضع الفهرسة في الأرشيف.

## 5. إحالة المعاملات ومتابعتها

من صف المراسلة يضغط الموظف المصرح له **إحالة**، ثم يختار الإدارة أو المكتب المستلم ويكتب توجيهاً واضحاً وتاريخ استحقاق عند الحاجة. تحفظ الإحالة في سجل النشاط ولا تستبدل السجل السابق.

تتدرج الحالة عادة من **جديدة** إلى **محالة** ثم **قيد المعالجة** ثم **منجزة**، ويمكن أرشفتها وفق الإجراء المعتمد. يستخدم زر **بدء** للانتقال إلى قيد المعالجة وزر **إنجاز** بعد إتمام المطلوب. تعرض صفحة مكتب المتابعة الحالات النشطة والمتأخرة وأحدث الإجراءات لتسهيل التصعيد الإداري.

## 6. القرارات والمناشير

تفتح صفحة **القرارات الإدارية** أو **المناشير الداخلية** وتستخدم نموذج التسجيل الخاص بها. يولد النظام رقماً رسمياً متسلسلاً ويحفظ البيانات الوصفية والجهة والتاريخ والموضوع.

> يلزم إرفاق ملف PDF صالح لكل قرار أو منشور. لا يكمل النظام الحفظ إذا لم يرفق PDF مؤرشف أو إذا كان الملف لا يحمل توقيع PDF صحيحاً.

يمكن ربط القرار أو المنشور بالمراسلات ذات الصلة لمتابعة الأثر المرجعي. يجب أن يراجع المستخدم الملف قبل الحفظ وأن يتأكد من النسخة النهائية المعتمدة إدارياً.

## 7. الأرشيف والبحث العربي

من صفحة **الأرشيف والبحث** يستطيع المستخدم البحث برقم المعاملة أو الموضوع أو الجهة أو نص المرفق المفهرس عبر OCR. تعرض النتيجة نوع السجل ورقمه وحالته ومؤشر OCR والمحتوى المتاح وفق صلاحيات المستخدم.

لا تعني ظهور نتيجة في البحث أن المستخدم مخول بتنزيل كل ملف؛ يستمر الخادم في فحص نطاق الإدارة والصلاحية عند كل طلب. يستخدم المسؤول النص المستخرج للمراجعة والتحسين، ولا يعدل المستند الأصلي بناءً على OCR دون الرجوع إلى الوثيقة المعتمدة.

## 8. التقارير ولوحات المتابعة

تعرض صفحة **التقارير والمؤشرات** الإحصاءات الرسومية للوارد والصادر والقرارات والمناشير، والتوزيع حسب الإدارة أو المكتب أو الجهة. تستخدم التقارير في متابعة حجم العمل والحالات المتأخرة ومتوسط الإنجاز، ولا تستبدل التقارير الرسمية التي تعتمدها الإدارة وفق اللوائح.

يعرض مكتب المتابعة قائمة المعاملات النشطة والمتأخرة وأحدث إجراء. يراجع المدير العام أو المستخدم التنفيذي المؤشرات ثم يتابع المعاملة من صفحة المراسلات أو الإحالة ذات الصلة.

## 9. إدارة المستخدمين وسجل التدقيق

تظهر صفحة **إدارة المستخدمين** للمسؤولين فقط. يستخدمها مدير النظام لإنشاء الحساب أو تحديث الاسم والدور والإدارة أو المكتب وتفعيل الحساب أو تعطيله. لا يُفعّل الموظف قبل إدخال بريده المؤسسي المعتمد، ولا ينشأ بريد افتراضي أو كلمة مرور نصية داخل النظام.

يسجل **سجل تدقيق الحسابات** التعديلات الإدارية المهمة، ويمكن للمسؤول المصرح له تصفيته وتصديره CSV للمراجعة. يمنع استخدام الحسابات المشتركة؛ لكل موظف حسابه وصلاحيته لتبقى المسؤولية قابلة للتدقيق.

## 10. التدريب المؤقت والانتقال إلى الخادم المحلي

يحفظ GitHub مصدر النظام والأدلة وحزمة التنصيب فقط. صفحة GitHub Pages تعريفية ولا تشغل قاعدة البيانات أو OCR أو تسجيل الدخول. التدريب العملي يحتاج بيئة تطبيق كاملة ببيانات تدريب غير حقيقية وحساب مستقل لكل متدرب.

عند جاهزية الخادم المحلي، يتبع مسؤول التقنية ملف `docs/TECHNICAL_HANDOVER_TIDC_LAN.md` ثم يشغل `Install-TIDC.cmd` و`Test-TIDC-Installation.ps1 -WriteReport`. ينقل الإعدادات المعتمدة فقط، وينشئ الأسرار الجديدة محلياً، ولا ينسخ ملف `.env` أو البيانات التجريبية إلى بيئة الإنتاج.

## قائمة مراجعة مختصرة للموظف

1. أسجل الدخول بحسابي الشخصي ثم أفتح الوحدة الصحيحة.
2. أسجل بيانات المعاملة كاملة قبل رفع المرفق.
3. أراجع المرفق وأتأكد أنه PDF أو صورة مسموح بها.
4. أحدد الإدارة وتاريخ الاستحقاق عند وجود إجراء مطلوب.
5. أحيل المعاملة بتوجيه واضح، وأحدّث الحالة عندما أبدأ أو أنجز العمل.
6. أبحث في الأرشيف قبل تكرار تسجيل مستند قائم.
7. أسجل الخروج عند انتهاء العمل.
