# خطة الوصول الشبكي الداخلي — TIDC

استناداً إلى ملف جرد أجهزة المركز المقدم، يحتوي الجرد على **11 جهازاً** وجميع العناوين المسجلة ضمن النطاق الخاص `192.168.1.0/24`. لا يعرض هذا المستند عناوين الأجهزة أو أسماء الموظفين تفصيلياً، ولا ينبغي إدخالها في الكود أو ملفات الإعداد أو قواعد جدار الحماية الفردية.

> يجب على مسؤول الشبكة تأكيد قناع الشبكة الفعلي، وتخصيص عنوان ثابت مستقل للخادم قبل تطبيق هذه الخطة. لا تستنتج الخطة عنوان خادم جديداً من عناوين الموظفين الموجودة في الجرد.

## التصميم المقترح

| العنصر | الإعداد المقترح | المسؤول |
|---|---|---|
| الخادم | جهاز الشؤون الإدارية بعنوان ثابت أو حجز DHCP منفصل عن أجهزة المستخدمين. | مسؤول الشبكة |
| الاسم الداخلي | سجل DNS داخلي `A` باسم `tidc.ly` يشير إلى عنوان الخادم الثابت. | مسؤول DNS |
| وصول المستخدمين | السماح لأجهزة شبكة المركز المعتمدة بالوصول إلى `https://tidc.ly:8443` فقط. | مسؤول جدار الحماية |
| الخدمات الداخلية | منع الوصول المباشر من أجهزة المستخدمين إلى MySQL وMinIO وOCR وClamAV. | مسؤول جدار الحماية / Docker |
| الشهادة | تثبيت شهادة الجذر الداخلية لـ Caddy على أجهزة المركز المخولة بعد التنصيب. | مسؤول الأنظمة |
| النطاق العام | يبقى `tidc.com.ly` معطلاً في هذه المرحلة، ولا يفعل إلا بقرار مكتوب وإعداد DNS وشهادة عامة مستقلين. | إدارة المركز / مسؤول النطاق |

## ترتيب التنفيذ

أولاً، يحجز مسؤول الشبكة عنواناً ثابتاً للخادم خارج نطاق عناوين DHCP الديناميكية أو يربط الحجز ببطاقة الشبكة الخاصة بالخادم. ثانياً، ينشئ سجل DNS داخلياً باسم `tidc.ly` موجهاً إلى هذا العنوان. ثالثاً، يختبر من جهاز موظف أن الاسم يحل إلى عنوان الخادم، ثم يشغل `Test-TIDC-Preflight.ps1 -TlsMode internal -Hostname tidc.ly` قبل بدء التنصيب.

بعد تشغيل النظام، يسمح جدار الحماية بمنفذ HTTPS الذي تعرضه الحزمة (`8443` في الوضع الداخلي الافتراضي) من نطاق شبكة المركز المعتمد فقط. لا تفتح منافذ MySQL أو MinIO أو OCR أو ClamAV للعملاء. تقوم بوابة Caddy باستقبال HTTPS، ثم تمرر الطلب للتطبيق داخل شبكة الحاويات المعزولة.

## ما لا ينبغي تنفيذه

لا يُنشأ جدار حماية منفصل لكل موظف اعتماداً على قائمة IP، لأن هذا يربط الوصول بجهاز قابل للتغيير بدلاً من سياسة الشبكة والحسابات المؤسسية. لا يُسجل عنوان IP لكل مستخدم داخل التطبيق إلا عندما تعتمد إدارة التقنية سياسة تدقيق واضحة ومدة احتفاظ محددة. لا يفتح `tidc.com.ly` أو المنفذان العامان 80 و443 من الإنترنت في الوضع الداخلي.

تتيح Caddy شهادات داخلية للأسماء غير العامة، لكن أجهزة العميل تحتاج إلى الثقة في شهادة الجذر الداخلية لتجنب تحذير المتصفح.[1] يشرح دليل الحزمة خطوات تصدير هذه الشهادة وتثبيتها، كما يشرح `docs/TIDC_DOMAIN_DEPLOYMENT.md` شرط DNS والمنافذ للنطاق العام.[2]

## عناصر الاستلام من مسؤول التقنية

| الدليل المطلوب | الحالة المطلوبة |
|---|---|
| عنوان ثابت أو حجز DHCP لخادم الشؤون الإدارية | مطلوب قبل التنصيب. |
| سجل DNS داخلي لـ `tidc.ly` | مطلوب قبل فحص ما قبل التنصيب. |
| قاعدة جدار حماية تسمح بـ 8443 من شبكة المركز فقط | مطلوب قبل فتح النظام للمستخدمين. |
| تثبيت شهادة الجذر الداخلية على أجهزة المستخدمين المخولة | مطلوب قبل التشغيل دون تحذير شهادة. |
| تقرير `Test-TIDC-Installation.ps1 -WriteReport` | مطلوب لتوثيق الاستلام. |
