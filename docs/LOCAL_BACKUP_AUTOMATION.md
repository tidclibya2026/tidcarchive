# النسخ الاحتياطي والاستعادة الدورية — TIDC

توجد الحزمة التشغيلية في `ops/backup/` و`ops/systemd/`. تنفذ نسخة مشفرة يومية لقاعدة البيانات وbucket مرفقات MinIO، ثم تختبر أسبوعيًا استعادة أحدث نسخة في قاعدة بيانات وbucket معزولين. لا تُشغل هذه الملفات في بيئة التجربة أو من دون عزل بيئة الاستعادة.

## الإعداد الآمن

أنشئ مستخدم نظام محدودًا باسم `tidcbackup`، ثم انسخ ملفات الخدمة والمؤقت إلى `/etc/systemd/system/` وامنح سكربتات النسخ حق التنفيذ. ضع القيم الحساسة في `/etc/tidc-archive/backup.env` بملكية `root:tidcbackup` وتصريح `640`. لا تضع الملف في Git أو في مجلد التطبيق.

يجب أن يضم ملف البيئة عناوين قاعدة البيانات وMinIO، حسابات الخدمة محدودة الصلاحيات، مسار التخزين الاحتياطي الداخلي، مستقبل مفتاح GPG، وجهة `rclone` خارج خادم التشغيل لنسخ الملفات المشفرة، وعدد أيام الاحتفاظ، وقاعدة بيانات وbucket منفصلين لاختبار الاستعادة. لا تستخدم قاعدة تشغيل النظام أو bucket الإنتاج كهدف اختبار.

بعد مراجعة الملف، فعّل المؤقتين عبر `systemctl enable --now tidc-backup.timer tidc-restore-verify.timer`. راجع النتائج من `journalctl -u tidc-backup.service` و`journalctl -u tidc-restore-verify.service`. ينجح الاختبار فقط إذا تحقق مجموع الملفات المشفرة، واستعيدت قاعدة البيانات المعزولة، وتطابق عدد كائنات MinIO المستعادة مع النسخة.

يلزم تثبيت `mysqldump` وعميل MySQL وعميل MinIO `mc` و`gpg` و`rclone` على الخادم المحلي فقط. تُشغَّل أول نسخة واختبار استعادة يدويًا بعد إعداد الأسرار، ثم يعتمد جدولا systemd: نسخة يومية عند 02:30 واختبار استعادة معزول أسبوعيًا يوم الأحد عند 04:30. لا يُعد نجاح فحص الصياغة أو بناء التطبيق بديلًا عن سجل تشغيل فعلي من خادم المركز.
