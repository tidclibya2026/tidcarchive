# دليل تنزيل وتنصيب وتشغيل نظام الأرشفة الإلكتروني TIDC

هذا الدليل مخصص لخادم الشؤون الإدارية في مركز المعلومات والتوثيق السياحي. يشرح تنزيل الحزمة، فكها في المسار `C:\Archiving`، وتشغيل ملف التنصيب الذي ينشئ بيئة عمل محلية آمنة. الاسم الداخلي الافتراضي للخادم هو **`tidc.ly`**، أما **`tidc.com.ly`** فهو خيار منفصل للنشر العام المعتمد فقط.

## 1. ما الذي يجب تنزيله؟

نزّل ملف الحزمة المضغوطة المسمى **`TIDC-Local-Installer-tidc.ly.zip`** من المحادثة، ثم انسخه إلى جهاز الخادم. لا تحتاج إلى تنزيل Node.js أو MySQL أو MinIO أو Python بشكل منفصل؛ تقوم الحاويات بتشغيل هذه المكونات داخل بيئة معزولة.

| العنصر | المتطلب أو المحتوى |
|---|---|
| نظام التشغيل | Windows 10/11 Pro أو Windows Server. |
| الذاكرة والمساحة | ذاكرة لا تقل عن 12 GB ومساحة حرة لا تقل عن 60 GB. |
| البرنامج المطلوب مسبقاً | Docker Desktop شغال مع WSL 2، أو محرك حاويات متوافق في Windows Server. |
| مسار التثبيت | `C:\Archiving` |
| اسم الخادم الداخلي | `tidc.ly` |
| رابط النظام بعد التنصيب الداخلي | `https://tidc.ly:8443` |

> تحتاج خدمة فحص الملفات إلى تواقيع مضاد فيروسات، لذلك قد يستغرق التشغيل الأول للحاويات وقتاً إضافياً لتنزيل التواقيع وتهيئتها.[1]

## 2. خطوات التنزيل وفك الضغط

أولاً، أنشئ المجلد `C:\Archiving` على جهاز الخادم. انقل ملف ZIP إليه، ثم انقر بزر الفأرة الأيمن واختر **Extract All**. يجب أن تظهر مجلدات مثل `ops` و`docs` و`client` و`server` مباشرة داخل `C:\Archiving`، لا داخل مجلد فرعي مضاعف.

بعدها، افتح **Docker Desktop** وانتظر حتى تظهر حالته Running. لا تبدأ التنصيب قبل تشغيل Docker؛ لأنه يشغل قاعدة البيانات والتخزين وعامل OCR وفحص الملفات والتطبيق نفسه.

## 3. تشغيل ملف التنصيب

افتح المجلد التالي:

```text
C:\Archiving\ops\local-windows
```

ثم انقر نقراً مزدوجاً على:

```text
Install-TIDC.cmd
```

يفتح هذا الملف PowerShell بطريقة مؤقتة وآمنة لتنفيذ `Install-TIDC.ps1`. لا يغير سياسة PowerShell على مستوى الجهاز؛ بل يسمح بتشغيل سكربت التنصيب لهذه العملية فقط.

تظهر لك الأسئلة التالية أثناء التنصيب. استخدم القيم الموضحة للإعداد الداخلي المعتاد:

| السؤال الذي يظهر | القيمة المقترحة |
|---|---|
| نمط HTTPS | اكتب `internal` أو اضغط Enter. |
| اسم DNS للنظام | اضغط Enter لقبول `tidc.ly`. |
| بريد مدير النظام المحلي | اكتب البريد المعتمد للمدير؛ أو اقبل القيمة الأولية إذا لم يعتمد البريد بعد. |
| كلمة المرور | أنشئ كلمة مرور جديدة لا تقل عن 10 أحرف ولا تستخدم كلمة المرور التجريبية في بيئة الخادم. |

## 4. ماذا يفعل ملف `Install-TIDC.cmd`؟

يستدعي الملف `Install-TIDC.cmd` سكربت `Install-TIDC.ps1` بالترتيب التالي:

1. يتحقق من وجود Docker ومن أن Docker Desktop يعمل.
2. ينسخ ملفات النظام إلى `C:\Archiving` إذا شغّل من موقع آخر.
3. يسألك عن نمط HTTPS واسم الخادم وبيانات المدير المحلي.
4. ينشئ ملف إعداد سري باسم `ops\local-windows\.env` ويولد مفاتيح عشوائية لقاعدة البيانات وMinIO وOCR والجلسات وتشفير المرفقات.
5. يقيد صلاحية ملف `.env` على مستخدم Windows الذي أجرى التنصيب؛ لا يرفع هذا الملف إلى Git ولا يرسل بالبريد.
6. ينفذ `docker compose up -d --build` لبدء الخدمات المحلية.
7. يعرض رابط HTTPS الصحيح عند نهاية التنصيب.

| الخدمة | دورها في النظام |
|---|---|
| `app` | واجهة النظام وواجهة البرمجة والصلاحيات. |
| `mysql` | قاعدة بيانات المستخدمين والمراسلات وسجل التدقيق. |
| `minio` | تخزين المرفقات والملفات المؤرشفة. |
| `ocr` | استخراج النص العربي من الصور وPDF. |
| `clamav` | فحص المرفقات قبل تخزينها. |
| `caddy` | بوابة HTTPS الوحيدة المتاحة لأجهزة المستخدمين. |

## 5. التحقق بعد التنصيب

بعد أن تظهر رسالة نجاح التنصيب، افتح PowerShell وشغّل الأمر التالي:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
C:\Archiving\ops\local-windows\Test-TIDC-Installation.ps1
```

يتحقق الملف من صحة تعريف الحاويات وحالة الخدمات ثم يطلب رؤوس HTTPS. يجب أن ترى رؤوس حماية مثل `Strict-Transport-Security` و`Content-Security-Policy` و`X-Frame-Options` و`X-Content-Type-Options`.

بعد نجاح الاختبار، افتح في متصفح الخادم:

```text
https://tidc.ly:8443
```

يجب أن تظهر شاشة تسجيل الدخول أولاً. استخدم بريد المدير وكلمة المرور اللذين تم إدخالهما أثناء التنصيب.

ينفذ ملف التنصيب تلقائياً فحصاً مسبقاً لـ Docker، والمساحة الحرة، والمنافذ، وذاكرة الجهاز، وحل اسم `tidc.ly` في DNS. يمكن تشغيله منفصلاً قبل التنصيب عند الحاجة:

```powershell
C:\Archiving\ops\local-windows\Test-TIDC-Preflight.ps1 -TlsMode internal -Hostname tidc.ly
```

ولإنشاء تقرير استلام لا يعرض الأسرار، شغّل:

```powershell
C:\Archiving\ops\local-windows\Test-TIDC-Installation.ps1 -WriteReport
```

يحفظ التقرير في `ops\local-windows\reports\` ويشمل حالة الحاويات ورؤوس الحماية فقط.

## 6. اعتماد شهادة HTTPS الداخلية

في النمط الداخلي، تنشئ Caddy شهادة محلية لـ `tidc.ly`. حتى لا يظهر تحذير في أجهزة الموظفين، يصدر مسؤول الخادم شهادة الجذر وينشرها على أجهزة المركز المخولة فقط:

```powershell
Set-Location C:\Archiving\ops\local-windows
docker compose --env-file .env cp caddy:/data/caddy/pki/authorities/local/root.crt .\tidc-internal-root.crt
```

بعد ذلك يثبت مسؤول التقنية الملف `tidc-internal-root.crt` في مخزن **Trusted Root Certification Authorities** عبر سياسة أجهزة المركز أو وفق إجراء إدارة الأنظمة. لا تنسخ أو توزع المفتاح الخاص للشهادة.

## 7. التشغيل والإيقاف وقراءة السجل

| الملف | الاستخدام |
|---|---|
| `Start-TIDC.cmd` | يبدأ الخدمات بعد إعادة تشغيل الخادم. |
| `Stop-TIDC.cmd` | يوقف الخدمات دون حذف قاعدة البيانات أو المرفقات. |
| `Show-Logs.cmd` | يعرض سجلات التطبيق وMySQL وMinIO وOCR للتشخيص. |
| `Test-TIDC-Installation.ps1` | يعيد التحقق من الخدمات والرؤوس الأمنية. |
| `Test-TIDC-Preflight.ps1` | يفحص متطلبات الخادم وDNS والمنافذ قبل التنصيب. |

لا تستخدم الأمر `docker compose down -v` لأن اللاحقة `-v` تحذف وحدات التخزين التي تحتوي قاعدة البيانات والمرفقات.

## 8. استخدام `tidc.com.ly` لاحقاً

لا تختَر `public` إلا إذا صدر اعتماد رسمي للوصول العام. في هذه الحالة يجب أن ينشئ مسؤول DNS سجلات `A` و/أو `AAAA` لـ **`tidc.com.ly`** نحو الخادم العام، وأن يفتح المنفذين 80 و443 إلى Caddy، ثم تعيد التنصيب باختيار `public` وتدخل البريد التشغيلي لمسؤول الشهادات. تتولى Caddy إصدار وتجديد شهادة عامة بعد نجاح تحقق DNS والمنافذ.[2] [3]

## 9. حلول سريعة للمشكلات الشائعة

| المشكلة | الإجراء الصحيح |
|---|---|
| تظهر رسالة أن Docker غير موجود أو غير شغال | ثبّت Docker Desktop، أعد تشغيل الجهاز إن طُلب ذلك، ثم افتح Docker وانتظر Running. |
| الرابط لا يفتح من جهاز موظف | تحقق من سجل DNS الداخلي لـ `tidc.ly` وجدار الحماية، ثم ثبت شهادة الجذر الداخلية على جهاز الموظف. |
| تحذير شهادة في المتصفح | نفذ خطوة تصدير شهادة الجذر وثبتها على الجهاز العميل؛ لا تتجاوز التحذير بشكل دائم. |
| فشل رفع ملف | افتح `Show-Logs.cmd`؛ يمكن أن تكون خدمة ClamAV في بداية تحميل التواقيع أو أن الملف غير مسموح أو غير آمن. |
| لا تظهر شاشة الدخول | استخدم نافذة خاصة في المتصفح أو امسح جلسة النظام السابقة، ثم افتح الرابط من جديد. |

## 10. النسخ الاحتياطي والمسؤولية التشغيلية

بعد نجاح التشغيل الأول، يكمل مسؤول الخادم إعداد النسخ الاحتياطي المشفر واختبار الاستعادة المعزول وفق `docs/LOCAL_BACKUP_AUTOMATION.md` و`docs/SECURITY_OPERATIONS.md`. تشمل النسخة الاحتياطية المشفرة قاعدة البيانات، مرفقات MinIO، ومفتاح `DOCUMENT_ENCRYPTION_KEY` ضمن إدارة أسرار منفصلة. لا تنقل ملف `.env` بين الخوادم أو بالبريد.
