# حزمة التنصيب المحلي لنظام TIDC

هذه الحزمة مخصصة لخادم يعمل بنظام **Windows 10/11 Pro أو Windows Server** في جهاز الشؤون الإدارية، في المسار المقترح `C:\Archiving`. تشغّل الحزمة التطبيق وقاعدة MySQL وتخزين MinIO وعامل OCR محلياً داخل حاويات معزولة. لا تتضمن الحزمة بيانات المعاملات أو صور المستندات الموجودة في بيئة التجارب؛ تُنقل تلك البيانات فقط من نسخة احتياطية معتمدة.

## المتطلبات

يتطلب الخادم اتصالاً داخلياً ثابتاً وشغّالاً أثناء الاستخدام، وذاكرة لا تقل عن 8 GB ومساحة حرة لا تقل عن 40 GB. يجب تثبيت **Docker Desktop** وتشغيله مع تفعيل WSL 2 أو استخدام Windows Server مع محرك حاويات متوافق. يلزم فتح المنفذ الداخلي الذي يحدده المسؤول، ويكون `8080` افتراضياً.

## التنصيب الأول

انسخ كامل مشروع النظام إلى `C:\Archiving`، ثم شغّل الملف `ops\local-windows\Install-TIDC.cmd` بالنقر المزدوج. يستخدم الملف PowerShell مؤقتاً لتجاوز سياسة التنفيذ للحلقة الحالية فقط، ثم يُنشئ ملف الأسرار المحلي ويبدأ الخدمات. يمكن للمسؤول بدلاً من ذلك تشغيل الأمر التالي من PowerShell بصفته مسؤولاً:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
C:\Archiving\ops\local-windows\Install-TIDC.ps1
```

تطلب أداة التنصيب بريد المدير وكلمة مرور جديدة لا تقل عن عشرة أحرف. تُنشأ مفاتيح قاعدة البيانات والتخزين وOCR عشوائياً، وتُحفظ في `ops\local-windows\.env`. لا يُرفع هذا الملف إلى Git ولا يرسل بالبريد.

بعد اكتمال التنصيب، افتح `http://localhost:8080`. للوصول من جهاز آخر بالشبكة الداخلية، استخدم اسم الخادم أو عنوانه الداخلي مع المنفذ نفسه بعد إعداد جدار حماية Windows وشهادة HTTPS داخلية معتمدة من إدارة التقنية.

> عند فتح الرابط لأول مرة في متصفح لا يملك جلسة صالحة، تظهر **شاشة تسجيل الدخول**. أما الجلسة المسجلة سابقاً فتعيد المستخدم إلى مساحة عمله مباشرة.

## التشغيل والصيانة

| الملف | الوظيفة |
|---|---|
| `Install-TIDC.cmd` | نقطة التنصيب المباشر بالنقر المزدوج على ويندوز. |
| `Start-TIDC.cmd` | بدء النظام بعد إعادة تشغيل جهاز الخادم. |
| `Stop-TIDC.cmd` | إيقاف الخدمات دون حذف البيانات. |
| `Show-Logs.cmd` | عرض آخر سجلات التطبيق وMySQL وMinIO وOCR للتشخيص. |
| `docker-compose.yml` | تعريف الخدمات المحلية؛ لا يعدّل إلا بواسطة مسؤول النظام. |

لا تستخدم `docker compose down -v` لأن الخيار `-v` يحذف أقراص قاعدة البيانات والمرفقات. النسخ الاحتياطي المشفر والاستعادة المعزولة يتطلبان تهيئة جهة تخزين خارجية ومفاتيح تشفير معتمدة، ثم تطبيق إجراءات `docs/LOCAL_BACKUP_AUTOMATION.md` في بيئة تشغيل مخصصة.

## نقل البيانات المعتمدة

قبل تشغيل النظام على الشبكة الداخلية، تنقل إدارة التقنية فقط نسخة MySQL ونسخة MinIO معتمدتين ومشفرتين، ثم توثق اختبار الاستعادة. لا تنقل ملف `.env` من بيئة أخرى ولا تستخدم كلمات مرور تجريبية.
